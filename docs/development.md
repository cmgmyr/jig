# Development

## How it runs

There is no build step and no npm dependency. Node runs the `.ts` files in `src/` directly through its built-in type stripping, so only erasable TypeScript is allowed: no `enum`, no `namespace`, no constructor parameter properties, `import type` for types, and `.ts` extensions on relative imports. `tsconfig.json` sets `erasableSyntaxOnly` and `verbatimModuleSyntax` so `tsc` flags anything Node would reject. Nothing reads it at runtime.

`package.json` holds only `"type": "module"`. Without it, `tsc` under `module: nodenext` treats `.ts` files as CommonJS and rejects every import. Do not add scripts or dependencies to it.

```
bin/wb          launcher (bash); the only user-facing command
bin/jig-run     dispatcher (bash); every wb-* on PATH is a symlink here
src/<name>.ts   one file per wb-<name> command
src/lib/        frontmatter parser, git helpers, workbench helpers, agent runner
templates/      AGENTS.md managed block, entry README, .workbench.yml
skills/         harness-neutral SKILL.md files
test/           unit tests, smoke test, typecheck
docs/assets/    logo SVGs, social preview, the demo and its generator
```

Adding a command is adding a file to `src/`. `install.sh` links it and `wb doctor` checks for it; nothing else needs registering. Add its name to `RESERVED_SLUGS` in `src/lib/workbench.ts` so no entry can shadow it.

## Checks

```sh
./test/typecheck.sh                                       # tsc --noEmit
"$(readlink ~/.config/jig/node)" --test test/*.test.ts    # unit tests
./test/smoke.sh                                           # end to end
```

`typecheck.sh` pulls TypeScript and `@types/node` from the npx cache and points `tsc` at it with `--typeRoots`, so the repo stays dependency-free.

`smoke.sh` installs into a temp directory using the path overrides in [configuration.md](configuration.md#test-only-overrides), creates a workbench there, and drives every command through the real `wb-*` symlinks. It stubs the headless agent with a shell one-liner and disables commit signing for its own commits. It touches nothing under your home directory. It needs a pinned Node: it reads `~/.config/jig/node`, falls back to Homebrew's `node@24`, and otherwise needs `JIG_NODE`.

All three run in CI on every pull request and push to `main`, on macOS and Linux.

## Conventions

- One command per file. Shared logic goes in `src/lib/`.
- Fail with `fail("message")` from `src/lib/workbench.ts`. It prints `wb: message` to stderr and exits 1. No stack traces reach the user.
- Never call `node` from PATH and never add a shebang to a `src/` file. The interpreter check lives in `bin/jig-run` and `install.sh` only.
- `wb doctor --fix` may relink, restore `CLAUDE.md`, refresh the managed block, and regenerate `INDEX.md`. It never deletes a real directory, edits an entry, or changes the pinned interpreter.
- Changing `templates/AGENTS.md` changes the managed block in every workbench on the next `wb doctor --fix`. Treat it like a schema change.
- Comments only where the next editor would otherwise get the line wrong. Everything else goes in these docs or the commit message.

## Assets

`docs/assets/demo.svg` is generated by `docs/assets/demo.py`, a dependency-free Python script. Edit the `script` list in it and run `python3 docs/assets/demo.py`. The wordmark in the logo files is Sora 600 converted to paths so GitHub renders it without a web font; the marks are hand-drawn SVG.

## Releasing

Bump `VERSION`, commit, tag. `wb doctor` compares it against each workbench's `.workbench.yml` and warns on drift; a migration step is not built yet and will arrive with the first `schema_version` change.
