# Data model

Everything in the workbench is plain markdown and git. You can read it in five years with no tooling, and you can edit any of it by hand except `INDEX.md`.

## Layout

```
~/workbench/
  AGENTS.md           managed block from jig, then your local notes
  CLAUDE.md           symlink to AGENTS.md
  .workbench.yml      name, schema_version, jig_version
  INDEX.md            generated by wb-index; never hand-edit
  inbox/              notes from wb capture, waiting for triage
  entries/
    <slug>/
      README.md       frontmatter plus the premise and decisions; yours
      log.md          one dated line per event, append-only; the agent's
      raw/            sources: links, clips, transcripts
```

## `.workbench.yml`

```yaml
name: personal
schema_version: 1
jig_version: 0.1.0
```

`name` is a label for this machine's workbench. `schema_version` is the entry format version and changes only with a migration. `jig_version` records which jig wrote the repo; `wb doctor` warns when it drifts from the installed jig.

## Entry frontmatter

```yaml
---
id: spades-game
title: Spades card game
status: active
premise: A Spades game I can play with family on web or iOS.
code: ~/Code/spades-poc
created: 2026-09-20
outcome: ""
tags: [games, swift]
schema_version: 1
---
```

| Key | Rule |
|---|---|
| `id` | Equals the directory name. Kebab-case: lowercase letters, digits, single hyphens. |
| `title` | Required. |
| `status` | One of `active`, `idle`, `cold`, `promoted`. Change it with `wb-set`, not by hand. |
| `premise` | One sentence. Shown in the index. |
| `code` | Optional. A path or URL to where the code lives. Entries point at code; they do not hold it. |
| `created` | `YYYY-MM-DD`. Set by `wb-new`. |
| `outcome` | Empty for `active` and `idle`. For `cold`, one line on why. For `promoted`, where it went. |
| `tags` | Optional inline list. |
| `schema_version` | Must match the workbench's. |

Last-touched dates are not stored. `wb-index` and `wb-stale` read them from `git log -1 --format=%cI -- entries/<slug>`, so the date is always right and never needs maintenance.

### Status meanings

- **active**: there is a next step you would take in the next 90 days.
- **idle**: still alive, no next step right now.
- **cold**: parked. Premise and a one-line reason are enough; the rest of the README can be empty.
- **promoted**: became a real project. `outcome` says where.

### The YAML subset

Frontmatter is parsed by a small parser in `src/lib/frontmatter.ts`, not a YAML library. It accepts flat `key: value` pairs, scalars (strings, numbers, booleans, quoted strings), and inline lists like `[a, b]`. It rejects nested maps, block lists, anchors, and multi-line strings. `wb doctor` reports any entry outside the subset. The point is that nothing clever can creep in and make the files hard to parse later.

## Entry README body

```markdown
## Premise

## Why now

## Open questions

## Next experiment

## Decisions
```

You own Premise and Decisions. The agent proposes edits and applies them only after you approve. The agent may add to Open questions and Next experiment on its own, and says so.

## `log.md`

One line per event, newest last:

```
- 2026-09-20: Created entry.
- 2026-09-21: Chose Swift over web for v1. Family plays on iPads.
- 2026-09-28: Status active -> cold. Family lost interest.
```

The agent appends a line whenever a decision is made or a question is answered. `wb-set` appends one on every status change. `wb-post` appends one after a session that changed the entry but wrote no line. Lines are never rewritten.

## `raw/`

Sources the entry depends on: links, pasted text, transcripts, exports. Each file starts with a one-line summary so the agent can skim the directory without reading everything. Name files `YYYY-MM-DD-<topic>.md`.

## `inbox/`

`wb capture` writes here. Each file is a dated note with the captured text. The next root session lists them and asks whether to turn each into an entry, fold it into one, or delete it. The inbox is not meant to hold anything for long.

## `INDEX.md`

Generated. Grouped by status in the order active, idle, promoted, cold; each group sorted by last commit, newest first. One line per entry with a link, the premise, and the last-touched date. Regenerated by `wb-index`, `wb-set`, `wb-post`, and `wb doctor --fix`. The agent reads it at the start of every root session.
